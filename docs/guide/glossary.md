# 常见词语解释

遇到不熟悉的词，按下面的解释理解即可。办理事情时，优先说明实际需求，不需要为了提交申请掌握所有技术细节。

## 申请和执行

| 词语 | 白话解释 |
| --- | --- |
| GitHub | 存放配置、讨论申请、审查变更和运行自动流程的平台 |
| 仓库 / Repository | 某一类工作的文件和历史记录放在一起的地方 |
| GitOps | 用 GitHub 等版本管理系统中经过审查的配置来管理资源的做法 |
| PR / Pull Request | 一份变更申请，展示你建议修改的内容，供别人讨论和审查 |
| 分支 / Branch | 先准备修改的工作副本，让尚未确认的变更有自己的位置 |
| main | 本体系中各仓库使用的主分支，通常保存已合并的配置 |
| 合并 / Merge | 将审查后的修改纳入目标分支；合并本身不保证云端执行成功 |
| Actions / Workflow | 在 GitHub 上运行的自动步骤，例如检查、预览和执行 |
| Terraform | 读取资源配置、计算变化并操作云资源的工具 |
| Terragrunt | 帮助组织多个 Terraform 配置，并安排依赖顺序的工具 |
| Plan | 变更预览：如果执行，将新增、修改或删除哪些资源 |
| Apply | 实际执行变更，使云资源接近已确认的配置 |
| State | 工具用来记住“哪些配置对应哪些实际资源”的记录 |

## 账号和权限

| 词语 | 白话解释 |
| --- | --- |
| 子账号 / 成员账号 | 公司云组织下，专门承载某类业务或环境资源的账号 |
| Landing Zone | 使用云服务前搭好的组织、账号和管理基础 |
| Account Vending Machine | 按配置自动创建子账号的工具，本体系的账号申请入口 |
| 基线 / Baseline | 新账号接入自动化管理时所需的一组基础设置 |
| Environment | 仓库运行流程时使用的环境，例如 test、prod；可以各自配置变量、授权和审批 |
| test / prod | 测试环境 / 正式业务使用的生产环境 |
| OIDC | 让阿里云核验 GitHub 工作流身份的一种方式 |
| RAM Role | 云账号中的一种权限身份；获准使用后，按该身份的权限操作 |
| 信任策略 | 规定哪些来源、仓库和环境可以取得某个角色身份的规则 |
| STS | 发放短期操作凭证的服务 |
| 零机密登录 | 这里指不在业务仓库保存长期云密钥，通过身份核验换取临时凭证；仍然需要授权 |
| OPA / Policy | 按统一规则自动检查变更的工具 / 检查规则；本体系中尚待接入 |

## 网络和网站

| 词语 | 白话解释 |
| --- | --- |
| IPv4 / IP 地址 | 网络用来定位设备或服务的一种地址 |
| 地址段 / CIDR | 一组地址的范围；实际分配记录在私有仓库中查看 |
| 地址池 / Pool | 集中管理、可按规则继续划分的一块地址范围 |
| IPAM | 公司网络地址的登记和管理工具，可以理解为“地址登记册” |
| Allocation | 一条具体地址分配或预留记录 |
| 机动池 | 为未来扩展和调整留出的地址余量 |
| VPC | 云账号里的一个独立虚拟网络，用来组织业务资源 |
| CEN / 云企业网 | 阿里云连接多个网络的服务；本体系的互联配置尚待建设 |
| GitHub Pages | 把本仓库的文档发布成可浏览网站的服务 |
| VitePress / Vue | 构建本站文档页面和交互界面使用的工具 |
