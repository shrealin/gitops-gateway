# 网络地址怎么申请

把内网地址想象成内部的门牌号。两个团队各自选择相同的门牌号，日后连接网络时就容易发生冲突。因此，**先统一登记地址，再建设业务网络。**

负责这件事的是 [iac-shared-network](https://github.com/shrealin/iac-shared-network)。IPAM 就是这里使用的“地址登记册”，用于记录地址范围如何规划、分配和使用。

本站只说明办理方式。真实地址、组织分配关系和网络拓扑，请在获准访问的私有仓库中查看。

## 先记住三条约定

1. 受统一管理的内网地址，使用前必须向共享网络仓库申请。
2. 先完成测试环境申请和验证，再单独申请生产；对应环境的登记生效后才可以使用。
3. 业务仓库读取已获准的地址来建设网络。自行挑选一个看起来空闲的地址，不代表已得到许可。

## 申请里需要准备什么？

在共享网络的私有仓库中，说明业务用途、负责人、预计规模、目标环境，以及是否需要与其他系统互通。

不熟悉地址大小的写法也没关系。先说明业务要连接哪些资源、预计需要多大规模，由维护者协助确认合适的方案。

## 从提出需求到获准使用

| 步骤 | 要做什么 | 怎样确认完成 |
| --- | --- | --- |
| 说明需求 | 说明用途、规模和环境 | 与维护者确认方案及影响范围 |
| 申请测试 | 提交测试环境的地址配置 PR | 审查、合并并执行成功 |
| 验证方案 | 确认地址可用，且不会干扰已有系统 | 在私有申请中记录验证结果 |
| 申请生产 | 单独提交生产 PR，引用测试结果 | 完成生产审查和执行 |
| 使用地址 | 业务仓库读取对应环境的登记 | 确认匹配正确，再创建并验证业务网络 |

完整办理步骤和通用申请模板见[办事指南](./requests#network)。

## 规划、批准和生效，有什么区别？

**规划**表示有了候选范围或预留安排。**批准**表示有人认可了申请。**生效**表示相应配置已经成功执行，登记实际存在。

只有对应环境的分配已生效，才可以按登记使用。测试环境验证通过，不会自动赋予生产环境的使用资格。

地址池是集中管理的一块范围；机动池是为未来变化保留的余量。它们都不是可以随意领取的地址清单。具体分配情况以私有仓库及实际运行记录为准。

## 登记地址，不等于打通网络

地址登记解决的是“门牌号不要重复”。让两个系统互相访问，还要明确连接通道、访问方向和允许的服务。

未来计划在共享网络仓库使用阿里云 **CEN（云企业网）**声明跨系统连接。这部分属于后续建设，不能因为地址已登记，就认为网络已经连通。

需要互通时，按[网络互联申请](./requests#connect)准备信息，并由双方负责人共同确认范围。

## 调整或释放地址时怎么做？

先确认哪些资源仍在使用这段地址，以及是否存在依赖它的连接和访问规则，再提出迁移或释放方案。

关闭分配、删除记录等操作可能影响已有业务。维护者需要检查变更预览和下游使用情况，完成迁移或验证后再执行。

## 到哪里看具体配置？

有权限的维护者可查看[共享网络仓库](https://github.com/shrealin/iac-shared-network)中的模块说明、地址登记和申请记录。

详细信息请留在私有仓库中讨论。本公开站点的 Issue、PR、截图和附件都不应用来收集实际地址、内部拓扑或业务访问清单。
